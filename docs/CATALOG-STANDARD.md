# Pause Catalog Standard

Pause is an **editorial index**, not an automated scrape. A source is admitted only when its canonical location, subject, original era, steward or publisher, and technical value can be independently verified.

## Source record

Every published record carries a stable accession code; title; canonical URL; optional preservation URL; source kind; subject area; original-era range; publication or release year when known; steward or publisher; a concise description; a specific explanation of lasting technical value; access conditions; rights or provenance notes; verification status; and the date on which the metadata was last checked.

The first release uses a controlled taxonomy: **Programming Languages**, **Operating Systems**, **Computer Architecture**, **Compilers and Toolchains**, **Networks**, **Databases**, **Graphics**, **Security**, **Source Code**, **Manuals**, **Oral Histories**, and **General Computing History**. The catalog may attach multiple subject tags to one source while retaining one primary subject for browsing.

## Verification status

| Status | Meaning | Publishing rule |
|---|---|---|
| `submitted` | A contributor supplied the source and supporting context. | Not visible in the public ledger. |
| `reviewed` | An editor checked the URL and basic metadata. | Not visible in the public ledger. |
| `verified` | The canonical source, scope, era, and descriptive annotation have been checked against a reliable steward or primary source. | Publicly visible. |
| `archived` | The source has a preservation copy, but the canonical publisher is unavailable or moved. | Publicly visible with an access note. |

## Editorial rule

The description must say **what the reader will find**. The “why it matters” note must identify a concrete technical use: tracing an operating-system decision, studying a compiler, understanding a machine interface, comparing an architecture, or reading the original development context. Nostalgia alone is insufficient.
